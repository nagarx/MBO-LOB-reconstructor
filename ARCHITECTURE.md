# Architecture

## Objective

The reconstructor must make a credible-looking but semantically or physically
misidentified book difficult to produce. The architecture therefore treats raw
semantics, source identity, causal availability, transactional mutation,
population custody, and bounded traceability as correctness requirements rather
than optional diagnostics.

## Invariants

### Source identity

Every qualified replay is bound to the bytes actually opened. Requested path,
opened canonical path, file size, SHA-256, DBN metadata, dataset, schema,
publisher, instrument mapping, date, decoder policy, and code/build identity are
verified before accepted output is reusable.

A filename is never evidence of symbol, venue, date, or schema identity. A hot
cache is another physical source and must be verified as such.

### Raw semantic preservation

The first canonical representation preserves raw DBN fields. It does not mutate
the book or prematurely collapse carriers. Policy-bound validation produces a
typed accepted or rejected event while retaining ordinal custody.

The universal carrier layer and XNAS policy layer remain separate:

- universal: field preservation, sentinel presence, byte ranges, source digest;
- XNAS-specific: permitted flags, side/action grammar, terminal sequence
  envelopes, reset/recovery policy, and causal observation time.

### Explicit lanes

Accepted events enter exactly one semantic lane:

- book command: A, C, M;
- reset control: R;
- trade-print carrier: T;
- resting-fill carrier: F;
- explicit no-op control: N.

Book mutation and analytical event flow are distinct. XNAS T and F are not
book reductions; C owns the reduction. Analytical consumers may observe T/F
only after their envelope commits.

### Transactional visibility

An open sequence candidate and its staged book are private. A complete terminal
envelope becomes observable only after:

1. its closure witness establishes causal availability;
2. envelope invariants pass;
3. all book commands apply to a private transaction;
4. endpoint and whole-book reconciliation pass;
5. the transaction and observation commitment are sealed.

On failure, none of the candidate's orders, levels, counters, witness payload,
digests, or feature-visible events enter live state.

### Failure ownership

Every failure has exactly one owner.

Identity-local market-data failures quarantine the candidate and invalidate the
affected identity. Other identities continue. While invalid, ordinary traffic
is quarantined; only a clean witnessed R recovery envelope can establish a new
valid epoch.

The following classes are replay-fatal:

- physical source, metadata, digest, decoder, mapping, or ordinal custody;
- configured member/block capacity exhaustion;
- arithmetic or counter overflow;
- impossible internal source/identity/commit invariants;
- terminal population or byte reconciliation failure.

Turning these into selective skips would censor data or hide a software defect.

### Population custody

Every attempted raw ordinal has one terminal disposition. Accepted,
rejected, quarantined, selected, witnessed, and excluded populations reconcile
in terminal receipts. A test counter generated by the same path is not an
independent oracle; live acceptance compares receipts with physical metadata and
an independently implemented reference where available.

### Causal time

Raw `ts_event` and `ts_recv` remain facts about individual carriers. The
feature-visible clock for an XNAS sequence envelope is
`effective_available_ns`, established by its closure witness. No downstream
state derived from that envelope may become visible earlier. The witness belongs
to its own subsequent candidate and cannot be counted twice.

## Data flow

```text
configured source expectation
        |
        v
open exact path -> hash/stat/metadata verification
        |
        v
raw DBN MBO + exact raw ordinal
        |
        v
RawMboEventV1 (lossless carrier)
        |
        v
source-policy validation
        |
        +--> rejected event + reason + custody
        |
        v
accepted semantic event
        |
        v
per-identity XNAS envelope candidate
        |
        +--> quarantine / INVALID / recovery state
        |
        v
closure witness + effective_available_ns
        |
        v
private exact-book transaction
        |
        v
committed observation + state digest + trace commitment
        |
        v
terminal source/replay/equivalence receipts
```

The extractor consumes only committed observations and terminally verified
receipts. It must not reconstruct event grammar independently.

## Ownership

| Responsibility | Authoritative owner |
| --- | --- |
| raw MBO carrier and source policy vocabulary | `hft-mbo-event-contract` |
| physical DBN identity and read custody | `loader::canonical` |
| XNAS sequence envelope and causal clock | `xnas::envelope` |
| exact order/level state and mutation | `xnas::book` |
| validity, quarantine, recovery, terminal replay | `xnas::mod` |
| two-pass execution, exact observation accounting, and equivalence identity | `xnas::qualified` |
| feature/target formulas and dynamic layout | feature extractor |
| normalization fit/apply policy | feature extractor |
| multi-artifact generation identity and publication | feature extractor |
| cross-repository schema allocation | root executable contract |

The same rule must not be handwritten independently in multiple owners. Tests
may implement an independent oracle, but they must clearly remain an oracle
rather than a second production authority.

## Strict versus compatibility APIs

`StrictDbnLoaderV1`, `StrictXnasReplayV1`, and
`XnasQualifiedReplayPlanV1` form the qualified path.

`MboMessage`, `LobReconstructor`, `LobState`, and general
statistics are compatibility primitives. Their public names do not imply
physical source identity, sequence-envelope timing, or generation
admissibility. They cannot mint a strict replay receipt.

The v1 boundary intentionally removed:

- every unqualified pathname-only file iterator;
- warning-and-drop conversion helpers;
- implicit hot-store path substitution;
- `DbnSource` on an infallible message trait;
- queue/lifecycle/trade analytics that collapsed T and F;
- basename-only hot-store resolution and cache preparation;
- reconstructor-owned Parquet writers and their warning-and-continue CLI.

Backward compatibility is not preserved when it would preserve silent
corruption. Historical artifacts are not reinterpreted; their producer version
and known limitations remain part of their custody record.

## Publication boundary

This repository does not publish a generation. That responsibility must be
implemented once in the feature extractor because publication spans book
receipts, rows, layouts, normalization/target metadata, diagnostics, and the
manifest.

A future generation transaction must:

- stage all files under one private generation directory;
- bind every artifact to one generation, source, config, schema, code, and
  dependency identity;
- compute metadata from the exact staged published population;
- reconcile attempted/accepted/rejected/aligned/published counts;
- fsync files and directories before one atomic visibility transition;
- leave an interrupted staging directory explicitly non-consumable;
- never overwrite or reinterpret a prior generation in place.

No writer in this crate can create a published data artifact. This keeps
generation transaction ownership singular at the extractor boundary.

## Observability

Strict replay traces are selective and deterministic. A consumer can bind a
predicate to source ordinal, identity, sequence, time range, event lane, or
anomaly and inspect:

```text
raw carrier
-> policy decision
-> envelope membership and witness
-> mutation/no-op decision
-> pre/post exact state commitment
-> committed snapshot
-> validity epoch and diagnostics
```

Diagnostics use stable names, units, and reason taxonomies. One counter cannot
change meaning by mode. Repair, quarantine, and rejection are distinct
populations.

## Performance policy

Correctness commitments are not weakened for throughput. Optimization is
permitted after a representative benchmark identifies cost and tests prove that
buffered/streaming, chunked/unchunked, and optimized/reference paths produce the
same commitments.

The observation digest currently adds measurable cost because it binds full
committed state. Reducing that cost requires a commitment-preserving design and
gate-power test, not removal of the bound fields.

## Non-goals

- No assumption that public order flow is predictive or profitable.
- No universalization of XNAS sequence grammar to other publishers.
- No model, label, horizon, sampling, or normalization preference.
- No claim that a passing unit suite proves corpus-wide correctness.
- No claim that a replay receipt alone establishes a complete scientific
  dataset or executable edge.
